# Verbosity report over the Olmo 3 / 3.1 stages (first run of `tools/verbosity_report.py`)

Step 2 of the #2002 plan: a small script that says, for any checkpoint's generations, how long and how padded the answers are and how that compares with a reference run on the same prompts. Run here on the 21 AlpacaEval generations of [`../2026-10-18_length`](../2026-10-18_length) (805 prompts each, each model's own chat template unless noted, temperature 0.6, top_p 0.95, 32K new tokens), with the Olmo 3 tokenizer. Reference for each family: its SFT `run1`. `rel1` = Olmo 3 model given the 3.1 release system prompt, `ctrl1` = default system prompt swapped for a control text, `rob1` = Robot/Acme persona control (see that folder's README).

Reports: [`results/7b_think.md`](results/7b_think.md), [`results/32b_think.md`](results/32b_think.md), [`results/32b_instruct.md`](results/32b_instruct.md) (JSON beside each). Columns: finished/total, runaway (hit the 32K cap), answer tokens median [IQR] and mean, thinking tokens median, per-answer non-empty lines / list items / bold spans / headings / table rows, share of answers with a URL or an emoji, and the over-answer rate: short prompts (≤ 120 characters) that got an answer of ≥ 500 tokens. The over-answer rate is a proxy, not a judgment: some short prompts ("write a story about …") deserve long answers, so compare it across stages on the same prompts rather than reading the level on its own; whether the extra length carries content is the question for the paired quality check planned in step 4. The second table compares each run with the reference over prompts finished in both: median per-prompt ratio of answer tokens with IQR, share answered longer, median token delta, and mean change in the formatting counts.

**What it adds to the earlier length numbers** (which it reproduces within a few percent: SFT → DPO median per-prompt ratio 1.50 at 7B Think, 1.32 at 32B Think, 1.65 at 3.1 32B Instruct in tokens here, against 1.53 / 1.31 / 1.64 in characters in `../2026-10-18_length`; that analysis used the prompts finished in all three stages of a family, this one the prompts finished in the two runs being compared):

| family | over-answer rate on short prompts, SFT → DPO → final | thinking median tokens, SFT → DPO → final | answers with an emoji, SFT → DPO → final |
|---|---|---|---|
| Olmo 3 7B Think | 63% → 84% → 67% | 938 → 1,160 → 2,218 | 27% → 45% → 29% |
| Olmo 3 32B Think (3.1 Think in brackets) | 64% → 77% → 70% (65%) | 864 → 1,141 → 1,444 (1,720) | 26% → 34% → 29% (48%) |
| Olmo 3.1 32B Instruct | 20% → 56% → 48% | – | 1% → 12% → 7% |

- DPO is the stage that turns short questions into long answers: the over-answer rate rises by 13–36 points at DPO and only partly comes back at the final (RL) stage.
- The final stage shortens answers relative to DPO but lengthens thinking: 7B Think's thinking doubles (1,160 → 2,218 tokens), 32B Think's grows by a quarter, and 3.1 32B Think thinks longer still (1,720).
- Formatting moves with length: at DPO each answer gains 7–17 non-empty lines, 4–7 list items and 6–9 bold spans; the final stage gives back part of the bold and headings (3.1 Instruct: bold +8.8 at DPO, +3.5 at final).
- The release system prompt raises the share of answers with a URL at the three Olmo 3 32B Think stages from 3.2–5.0% to 9.1–11.0% (`rel1` rows), and 3.1 32B Think, whose own template carries that prompt, is at 12.7% (5.1% with the control prompt); the same effect as in [`../2026-10-19_olmo-voice`](../2026-10-19_olmo-voice). For 3.1 32B Instruct the swap raises it at DPO (7.1% → 12.0%) but not at SFT (4.6% → 3.0%).
- Emoji and dingbats (✅ ⚠️ 🚀 …) appear in 45% of 7B Think DPO answers against 27% at SFT, and in 48% of 3.1 32B Think answers; the DPO data itself carries this (chosen answers have emoji 3× as often as rejected, see [`../2026-10-20_dpo-pairs`](../2026-10-20_dpo-pairs)).

**Reproduce.** `python tools/verbosity_report.py --tokenizer allenai/Olmo-3-7B-Think --per-dataset --reference SFT.jsonl SFT.jsonl DPO.jsonl FINAL.jsonl --out-md report.md --out-json report.json`; the three runs here took 40–105 s each on CPU (`run_verbosity.sh`). Raw generations stay on the GPU machine (they answer some harmful prompts); the JSONL format is the one `generate_length.py` writes: `instruction`, `response`, `finish_reason`, `dataset`, `index`.
